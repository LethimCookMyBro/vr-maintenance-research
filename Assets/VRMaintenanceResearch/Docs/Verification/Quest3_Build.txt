The three errors
----------------
All three are the same NullReferenceException, thrown inside Unity's own OpenXR
project-validation pass, not by this project:

  MetaQuestFeature.cs:554, in a lambda from CreateValidationRules,
  reached from OpenXRProjectValidationBuildStep.OnPreprocessBuild

The rule at MetaQuestFeature.cs:552 reads

  OpenXRSettings.GetSettingsForBuildTargetGroup(EditorUserBuildSettings.selectedBuildTargetGroup)

- the editor's SELECTED build target group - rather than the group being validated,
then calls GetFeature<MetaQuestFeature>() on the result. MetaQuestFeature exists only
in the Android feature list, so whenever the selected group is Standalone the feature
is null and the rule dereferences it. This build switched the ACTIVE target
programmatically, which leaves the selected group unchanged, so the condition was met.
Using the Build Settings window would not reproduce it.

The build still succeeded because the pre-process callback catches the exception. The
cost is that the rest of the validation pass is abandoned, so a successful build log
is not by itself evidence of a clean OpenXR validation.

Validation was therefore run separately with the selected group matching, and
recorded in OpenXR_Validation.txt: no issues on Android, no issues on Standalone.

Restored afterwards
-------------------
The active build target was returned to StandaloneWindows64. The Android build had
also written platform state into version-controlled files - two Android XR settings
appended to PlayerSettings.preloadedAssets, m_optimizeBufferDiscards flipped on the
Android OpenXR settings, URP shader-stripping prefilter flags recomputed on two
quality assets, and TMP dynamic font atlases touched by play mode. All were reverted;
they regenerate on the next build for whichever platform.

Re-verified after the restore: scene integrity 7/7 PASS, visual validator ALL SCENES
PASS with no warnings, full flow walkthrough A-B WALKTHROUGH PASSED, zero console
errors.
